# Jev mail integration — implementation and staging validation

This change implements the mail relevance work from [the follow-up investigation](jev-mail-relevance-2026-09-21.md): one shared Jev assessment for mail organization, the Brief, attention views, search and proof-category filtering. Settings has a dedicated **Jev** section without a model selector.

## User-visible behavior

- Newsletters and promotions are excluded from Brief eligibility by default. Direct delivery, a familiar university domain or a tracked promotional message does not override that gate. Explicit sender, mailing-list or thread corrections can include/exclude candidates.
- Reply, required action, waiting and meaningful account/booking changes are independent, evidence-backed facts. Reading a message does not complete its obligation. The new mail views are Needs reply, Needs action, Waiting for and Changes.
- The Brief considers indexed obligations before its recent-mail shortlist. The fourth reply no longer disappears behind an answer-lane cap. Eligible overflow is retained, counted separately from noise, and available in an expandable backlog.
- Today's latest Brief projects current facts: completed requests disappear, changed obligations move to the appropriate lane, and overflow fills freed highlights. Historical editions remain snapshots. Successfully persisted display editions record surfaced revisions; a cancellation is deduplicated by the original change message, including after a later reply.
- Search preserves retrieval order, strongest matching message excerpts and account identity. It advances selective full-text queries with continuation tokens, reranks a broader authorized candidate pool before clipping, and preserves relevance through account merges and the inbox UI. An explicit promotion query can still rank a promotion first. Recent-order preference is carried through account merging.
- The reader can show classification reasons and copied source evidence. Settings exposes incoming classification, Brief eligibility, search relevance, explanation visibility, follow-up age, recent classification counts, exact corrections and an explicit mailbox recheck. Changes persist immediately, with optimistic revision checks against conflicting browser tabs.
- Work proof offers respect the current shared Jev/user-rule category before obsolete legacy model categories. Jev does not send messages, complete Work, file calendar events or change the user's mailbox folders.

## Model, storage and failure behavior

The only mail classifier provider path is OpenRouter Decisions with fixed `typesafe/jev-1.13`; generative prose settings remain separate. The returned version, question version, source revision, probabilities, status and source evidence are persisted. Existing OpenRouter credential, entitlement, budget and usage rules apply. Missing setup is visible in Settings; provider errors are sanitized.

Question set `mail-1` asks purpose, subject, reply/action/waiting/change and independent evidence-source questions. Code copies source text and owns policy, elapsed time, ranking, pagination and rendering. A completed/cancelled request can clear the old duty; a cancellation with an automatic refund is still a new material change.

Classification runs after sync and from a five-minute retry cron. An indexed migration queues old corpus rows in batches of 100. Each sweep uses four concurrent evaluations and at most 48 threads, with a 40-second scheduling budget, then schedules remaining work. Convex leases prevent duplicate workers; message/revision/lease checks prevent stale writes. Failures back off and stop after three attempts until content changes or the user requests a recheck. Metadata-only sync preserves hydrated bodies, headers, recipients and full-text evidence, and cannot reopen an exhausted retry loop. Text bodies retain quote/newline boundaries.

Context is bounded to 16 recent messages plus earlier obligation evidence, with 2,400 body characters per message. Incomplete history or truncated content is recorded as uncertain. One supporting message is stored per obligation kind; this is thread-state classification, not an unlimited atomic task extractor. The attention views are paginated; the Brief candidate scan is bounded (up to 150 per attention kind). Interactive relevance has a two-second evaluation deadline, four concurrent chunks, per-user/content caching and retrieval-order fallback. A reranker cannot retrieve absent candidates; this release does not claim universal paraphrase recall or semantic perfection.

No independent Jev routing, Area matching, Work-shape, document-review or automatic completion system is introduced by this mail change. Those experimental applications in the broader research require separate task-specific evaluations; existing consumers can reuse the shared mail facts without adding a classifier per screen.

## Evaluation and release checks

The production question probe uses 16 frozen synthetic mail cases and the real transport/assessment code (`scripts/eval-jev-mail.ts`). The [initial run](jev-2026-09-21/production-question-probe-initial.json) passed 15/16: the evidence question incorrectly treated an automatically refunded cancellation as resolved. The [second run](jev-2026-09-21/production-question-probe-second.json) passed 15/16: an incoming approval request was also labelled waiting. The evidence question now distinguishes a reported change from an outstanding duty; waiting explicitly requires an outbound request or another person's inbound promise.

The [final run](jev-2026-09-21/production-question-probe.json) passed 16/16, with median 297 ms, p95 730 ms and reported cost $0.001729392. This is a development regression set used to refine prompts, not a held-out accuracy estimate, production SLA or guarantee of deterministic semantic correctness. All probe inputs are synthetic. The historical Syracuse Athletics Brief and its real messages have not been replayed.

Focused tests cover typed response validation, provider failure/cancellation, bounded concurrency, evidence and source-version checks, retries, tenant/account isolation, partial resync, historical-context anchors, persistent corrections, settings authentication/revisions, default Brief exclusions, resolution/backlog projection, metadata migration, relevant search pagination/order, pricing and fixed-provider credential policy. The complete test suite, typecheck, lint, production build and staging deployment must pass before release is called complete.

Deployment target: the existing `staging` branch workflow, Convex development deployment and Railway project `lab86-mail`, environment `development`, service `web`, at https://mail-staging.lab86.io. The ordinary background migration/retry crons and sync kicks start classification; Settings shows progress and offers rechecking. Production is not a deployment target for this change.
